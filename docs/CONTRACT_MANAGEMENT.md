# 契約・月会費の管理

- プラン、料金、休会、退会、復帰は会員の「月額プラン履歴」で設定します。
- 「この月のみ」は翌月の契約を変えません。「この月から次の設定まで」は、登録済みの次の変更・復帰予定を残します。
- 基本情報の編集からは契約金額・状態を変更できません。同姓同名の新規登録では既存会員への導線を表示します。
- 月の途中まで有効だった契約は、その月の会費に含めます。入会は最初の課金月、退会は最後の課金月で数えます。
- 契約額と実際の入金額は別管理です。メモだけでは入金済みになりません。契約訂正で入金済み金額は変わりません。
- 過去の料金が不明な場合は「料金未設定」として表示し、現在料金や標準料金で補いません。

## 保存と復旧

契約の正本は `membership_history` です。会員詳細、履歴、売上一覧、売上グラフ、経営レポートは `membership-ledger.ts` の共通判定を使います。

`save_member_contract` は会員単位でロックし、期間の分割・契約・入金・現在情報を一つのトランザクションで保存します。途中の失敗は全体が巻き戻ります。期間の重複はデータベースの制約で拒否します。

`membership_change_log` に変更前後、実行者、日時を記録します。移行前の全契約も `BASELINE` として保存しています。復旧時は対象会員・対象期間の変更前データを確認し、契約設定から訂正します。

`users.plan/status/monthly_fee` は現在情報の写しです。直接変更は拒否します。日本時間の毎日0時に `/api/cron/memberships` が同期し、予約済みのプラン変更も日付に合わせて反映します。

## 検証

`npm run test:membership` で過去料金保持、月替わり、休会・復帰、予定保持、二重保存防止、入金保持、失敗時の巻き戻し、画面操作を検証できます。画面検証にはローカルサーバーが必要です。`PLAYWRIGHT_BASE_URL` で接続先を指定できます。

2026-11-04の監査では74名を確認し、移行後の期間重複は0件です。金額の根拠を確認できない旧契約は、推測せず未設定として扱います。
